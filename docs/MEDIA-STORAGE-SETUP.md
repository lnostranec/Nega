# Хранилище фото (Yandex Object Storage)

Фото товаров и подарочных сертификатов загружаются из админки через `/api/admin/upload`.
Файлы уходят в S3-совместимый бакет; без настроек в проде загрузка возвращает 503,
локально файлы пишутся в `public/uploads/products`.

Поддерживаются JPG, PNG, WebP, GIF до 5 МБ.

---

## 1. Создать бакет

1. [console.yandex.cloud](https://console.yandex.cloud) → каталог, где живёт база.
2. **Object Storage** → **Создать бакет**.
3. Имя: `nega-media` (или своё, оно попадёт в URL).
4. Класс хранения — «Стандартное», доступ на чтение — **публичный**.

## 2. Открыть объекты на чтение

В настройках бакета: **Доступ на чтение объектов** → «Публичный».
Если через политику доступа, нужен анонимный `viewer` для объектов:

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Principal": "*",
      "Action": ["s3:GetObject"],
      "Resource": "arn:aws:s3:::nega-media/*"
    }
  ]
}
```

Загрузка при этом остаётся закрытой — её делает сервер по ключам.

## 3. Сервисный аккаунт и ключи

1. **Identity and Access Management** → **Сервисные аккаунты** → создать `nega-storage`.
2. Роль: `storage.editor` (или `storage.uploader`, если нужен только upload).
3. Для аккаунта: **Создать новый ключ** → **Создать статический ключ доступа**.
4. Сохранить `key_id` и `secret` — второй раз секрет не покажут.

## 4. Переменные окружения

Локально — в `.env`, на Vercel — **Production и Preview** (иначе на preview-деплоях загрузка вернёт 503):

```env
S3_ENDPOINT=https://storage.yandexcloud.net
S3_REGION=ru-central1
S3_BUCKET=nega-media
S3_ACCESS_KEY_ID=...
S3_SECRET_ACCESS_KEY=...
S3_PREFIX=products
# Необязательно: свой домен или CDN вместо storage.yandexcloud.net
# S3_PUBLIC_BASE_URL=https://media.nega.ru
```

После добавления переменных — **Redeploy**: значения читаются при сборке и в рантайме.

## 5. Проверка

1. `/admin/products` → любой товар → «+ добавить фото» → выбрать файл.
2. В ответе и в превью должен появиться URL вида
   `https://storage.yandexcloud.net/nega-media/products/2026/11/<uuid>.jpg`.
3. Ссылка открывается в браузере без авторизации.
4. Адрес вида `http://localhost:3000/uploads/products/...` после настройки появляться не должен.

## 6. Что учесть

- **Старые фото** из `public/uploads` (если они уже попали в товары) на Vercel отдавать нечем —
  их нужно загрузить заново через админку.
- **`next.config.ts`** автоматически добавляет домен хранилища в `images.remotePatterns`
  (берётся из `S3_PUBLIC_BASE_URL` или `S3_ENDPOINT`). Если подключите CDN — задайте
  `S3_PUBLIC_BASE_URL`, иначе `next/image` не пропустит новый домен.
- **Ключи в браузер не попадают**: загрузка идёт через серверный route, доступ проверяется
  по `requireAdminUser()`.
- **Свой домен**: в Object Storage можно включить хостинг + TLS-сертификат и получить
  `https://media.nega.ru` вместо длинного адреса.

## 7. Резервный вариант без облака

Пока бакета нет, фото можно положить в репозиторий (`public/NegraPhoto/...`) и указать путь
при наполнении каталога — но заказчица не сможет делать это сама, а каждая правка потребует
деплоя.
