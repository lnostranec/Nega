# Уведомления в ВКонтакте

Уведомления магазина уходят **в сообщество ВКонтакте** — раньше это был Telegram, но `api.telegram.org` из российских дата-центров работает нестабильно, а ВК доступен всегда. Миграция выполнена в коммите `c426cb1`.

## Что отправляется

| Событие | Откуда | Что в сообщении |
|---|---|---|
| Заявка «Перезвоните мне» | `POST /api/consultation` | имя, телефон, время (МСК), комментарий |
| Новый отзыв | `POST /api/reviews` | оценка, автор, текст, ссылка на модерацию |

## Как реализовано

`src/lib/vk.ts` → `POST https://api.vk.com/method/messages.send`, без SDK.

- токен передаётся в теле запроса (не в URL — чтобы не оседал в логах);
- у каждого сообщения свой `random_id` — защита от дублей;
- таймаут 8 секунд;
- несколько получателей через запятую, ошибка бросается только если не дошло ни до одного;
- без ключей сообщение пишется в лог сервера (удобно локально);
- ошибки ВК приходят с HTTP 200 в поле `error` — код и текст попадают в лог.

## Переменные окружения

```env
VK_TOKEN=vk1.a...        # ключ доступа сообщества, право «Сообщения сообщества»
VK_PEER_ID=140141604     # один id или несколько через запятую
```

`/api/health` показывает `"vk": "ok"`, если обе переменные заданы.

## Виды `peer_id`

| Куда шлём | `peer_id` | Кто увидит |
|---|---|---|
| Личный диалог с человеком | положительное число — id пользователя, напр. `140141604` | только он |
| Беседа (групповой чат) | `2000000000 + chat_id`, напр. `2000000123` | **все участники беседы** |
| Само сообщество | отрицательное, напр. `-123456789` | не диалог — стена/обсуждения |

**Текущее состояние: `VK_PEER_ID=140141604` — личный диалог (владелец).**
**Планируется: заменить на id заказчицы, когда проект будет передаваться.**

## Важное ограничение: сообщество не может написать первым

ВК разрешает сообществу отправлять сообщение пользователю только после того, как **этот пользователь сам написал сообществу** (или разрешил сообщения от сообществ в настройках). Иначе возвращается ошибка:

- `901` — Can't send messages for users without permission
- `902` — Can't send messages to this user due to their privacy settings
- `7` — Permission to perform this action is denied

Для сайта это означает: форма покажет «не удалось отправить», а заявка не дойдёт. Поэтому при смене `VK_PEER_ID` соблюдайте порядок.

## Как переключить уведомления на заказчицу

1. Заказчица открывает сообщество Nega → «Написать сообщение» → отправляет любое сообщение («привет»).
2. Убедиться, что её сообщение видно в разделе «Сообщения» сообщества.
3. На Vercel заменить `VK_PEER_ID` на её id. Можно указать обоих:
   ```env
   VK_PEER_ID=140141604,123456789
   ```
4. Redeploy.
5. Проверить: оставить заявку на сайте (иконка трубки в шапке) и убедиться, что сообщение пришло.

Разрешение сохраняется, пока пользователь не заблокирует сообщество или не удалит диалог с ограничением.

## Альтернатива: беседа вместо личных сообщений

Если уведомления должны видеть несколько человек и не должно зависеть от «кто написал первым», лучше слать в **беседу**:

1. Создать беседу через API `messages.createChat` с параметром `community_ids` (вручную через интерфейс ВК сообщество в чат не добавить) либо использовать существующую беседу с сообществом-участником.
2. Узнать `chat_id` — число в адресе беседы: `vk.com/im/convo/123456789` → `chat_id = 123456789`.
3. `VK_PEER_ID=2000000123456789` (то есть `2000000000 + chat_id`).
4. Redeploy.

Плюсы: видят все участники, история и обсуждение в одном месте, не нужны «разрешения» от каждого. Минус: нужно один раз создать беседу.

## Ограничения текущей реализации

- Нет очереди и повторов: не доставилось — в логах ошибка, повторно не отправится. Для заявок это приемлемо; при необходимости можно складывать в таблицу и досылать по cron.
- Нет параметра `disable_mentions`: если в тексте отзыва попадётся `@all` или упоминание, ВК может разослать уведомления участникам. Стоит добавить `disable_mentions: 1`.
- Лимиты ВК на частоту сообщений не обрабатываются отдельно — при массовых уведомлениях возможен `flood control` (код 9).
